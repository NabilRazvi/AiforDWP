# Startup Program Audit and Safe Management Script

This folder contains a PowerShell 5.1 script for safely auditing, disabling, and restoring Windows startup programs.

Script:
- `startup-program-audit-safe.ps1`

## What the script does

The script audits startup items from common startup locations and can safely disable them by name.

Safety-focused behavior:
- Supports dry run mode that never changes endpoint state.
- Captures rollback data before any disable action.
- Creates registry backups before disabling registry startup values.
- Moves startup folder files to a backup location instead of deleting them.
- Supports rollback from a generated rollback state file.
- Logs every action and prints a clear summary at the end.

## Startup locations audited

The script reads startup items from:
- Current User startup registry location: `HKCU:\Software\Microsoft\Windows\CurrentVersion\Run`
- Local Machine startup registry location: `HKLM:\Software\Microsoft\Windows\CurrentVersion\Run`
- Startup folder for current user
- Common startup folder

## Parameters and options

`-DryRun`
- Lists startup items and shows what would happen.
- Makes no changes.

`-DisableName <string>`
- Disables startup items matching the provided startup program name (case-insensitive exact match).
- Can match one or more items across registry and startup folders.

`-Rollback`
- Switches to rollback mode.

`-RollbackFile <string>`
- Path to a rollback state JSON file generated by a previous disable run.

`-WorkingRoot <string>`
- Optional path override for backup and rollback storage.

## How to run dry run mode

Dry run listing:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ".\Day3\startup-program-audit-safe.ps1" -DryRun
```

Dry run disable preview:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ".\Day3\startup-program-audit-safe.ps1" -DisableName "OneDrive" -DryRun
```

## How to disable a startup program by name

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ".\Day3\startup-program-audit-safe.ps1" -DisableName "OneDrive"
```

When disabling:
- Registry entries are backed up first to a `.reg` file.
- Startup folder entries are moved to a backup folder.
- A rollback state JSON file is created and reported in the summary.

## How rollback works

A successful disable run creates a rollback state file under the rollback-state folder.

To restore:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ".\Day3\startup-program-audit-safe.ps1" -Rollback -RollbackFile "C:\Users\labuser\Documents\Training\Day3\startup-work\rollback-state\startup-rollback-YYYYMMDD-HHMMSS.json"
```

Rollback behavior:
- Registry items are restored from saved item details.
- If direct restore fails, the script attempts to import the associated `.reg` backup.
- Startup folder files are moved back to their original startup folder path.

Rollback dry run:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ".\Day3\startup-program-audit-safe.ps1" -Rollback -RollbackFile "C:\Users\labuser\Documents\Training\Day3\startup-work\rollback-state\startup-rollback-YYYYMMDD-HHMMSS.json" -DryRun
```

## Where logs and backups are stored

By default (under Day3):
- Logs: `logs\startup-audit-YYYYMMDD-HHMMSS.log`
- Registry backups: `startup-work\registry-backups\`
- Startup file backups: `startup-work\startup-file-backups\`
- Rollback state files: `startup-work\rollback-state\`

You can override backup and rollback storage with `-WorkingRoot`.

## Production safety notes

- Use `-DryRun` first on production endpoints.
- Run with administrative privileges when modifying Local Machine startup entries.
- Permission errors are logged per item and the script continues processing.
- The script avoids permanent deletion and preserves rollback paths for managed items.
