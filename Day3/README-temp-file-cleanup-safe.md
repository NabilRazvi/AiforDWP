# Temp File Cleanup Safe Script

This folder contains a PowerShell 5.1 script for safe temp file cleanup on a Windows endpoint.

Script:
- `temp-file-cleanup-safe.ps1`
- `temp-cleanup.ps1` (compatibility wrapper for older command examples)

## What the script does

The script cleans up temp files safely by moving them into a timestamped rollback store instead of deleting them immediately. This allows a previous cleanup run to be reversed if needed.

It supports:
- Dry run mode
- Configurable file age filtering
- Per-file error handling
- Locked file detection and skip behavior
- Timestamped logging
- End-of-run summary
- Rollback using a generated manifest
- Compatibility aliases for older command names

## Default target locations

In cleanup mode, the script targets these locations by default:
- `$env:TEMP`
- `$env:WINDIR\Temp`

You can override these by passing `-TargetPaths`.

## Parameters

### Cleanup mode parameters

`-DryRun`
- Shows the files that would be moved to the rollback store.
- Does not move or delete any files.

`-OlderThanDays <int>`
- Only targets files older than the specified number of days.
- Default: `0`
- Example: `-OlderThanDays 7`

`-TargetPaths <string[]>`
- Optional list of folders to scan instead of the defaults.
- Example: `-TargetPaths "C:\Users\User1\AppData\Local\Temp","C:\Windows\Temp"`

`-WorkingRoot <string>`
- Optional path for the script working area.
- This area stores rollback content and manifests.
- Default location: a `cleanup-work` folder under Day3.

### Rollback mode parameters

`-Rollback`
- Switches the script into restore mode.
- Must be used with `-RollbackManifestPath`.
- Compatibility alias: `-EnableRollback`

`-RollbackManifestPath <string>`
- Path to the CSV manifest generated by an earlier cleanup run.
- Required when using `-Rollback`.
- Compatibility alias: `-RollbackFromManifest`

`-DryRun` in rollback mode
- Shows the files that would be restored from a manifest.
- Does not move any files back during the rollback dry run.

## Output folders

The script creates the following folders under Day3 by default:
- `logs`
- `cleanup-work\rollback`
- `cleanup-work\manifests`

## Logging

Every action is written to a timestamped log file.

Example log location:
- `Day3\logs\temp-cleanup-YYYYMMDD-HHMMSS.log`

The log includes:
- Run metadata
- Files found
- Files skipped
- Files moved
- Restore actions
- Errors
- Final summary

## Summary counters

At the end of each run, the script reports counters including:
- `FilesScanned`
- `CandidateFiles`
- `FilesMovedToRollback`
- `FilesRestored`
- `FilesSkippedLocked`
- `FilesSkippedMissing`
- `FilesSkippedInUse`
- `FilesSkippedAlreadyExists`
- `FilesFailed`

## How rollback works

In cleanup mode, files are moved to a rollback folder and a manifest CSV is written.

The manifest records:
- Original path
- Rollback path
- Last write time
- File length
- Cleanup timestamp

To restore files later, run the script with `-Rollback` and provide the manifest path.

Important:
- `manifest-YYYYMMDD-HHMMSS.csv` in the example below is a placeholder, not a real file name.
- Replace it with an actual manifest created by a cleanup run.
- Rollback is only meaningful after a real cleanup run that moved files into the rollback store.
- A dry run can show candidates, but it does not create rollback content you can restore from.

## Examples

Dry run using default locations:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ".\Day3\temp-file-cleanup-safe.ps1" -DryRun
```

Compatibility form from inside Day3:

```powershell
.\temp-cleanup.ps1 -DryRun
```

Dry run for files older than 7 days:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ".\Day3\temp-file-cleanup-safe.ps1" -DryRun -OlderThanDays 7
```

Cleanup for files older than 7 days:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ".\Day3\temp-file-cleanup-safe.ps1" -OlderThanDays 7
```

Cleanup using custom target paths:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ".\Day3\temp-file-cleanup-safe.ps1" -OlderThanDays 3 -TargetPaths "C:\Users\User1\AppData\Local\Temp","C:\Windows\Temp"
```

Rollback a previous cleanup run:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ".\Day3\temp-file-cleanup-safe.ps1" -Rollback -RollbackManifestPath "C:\Users\labuser\Documents\Training\Day3\cleanup-work\manifests\manifest-YYYYMMDD-HHMMSS.csv"
```

Example with a real manifest file name:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ".\Day3\temp-file-cleanup-safe.ps1" -Rollback -RollbackManifestPath "C:\Users\labuser\Documents\Training\Day3\cleanup-work\manifests\manifest-20260805-051533.csv"
```

Compatibility form from inside Day3:

```powershell
.\temp-cleanup.ps1 -EnableRollback -RollbackFromManifest "C:\Users\labuser\Documents\Training\Day3\cleanup-work\manifests\manifest-20260805-051533.csv"
```

Rollback dry run using the compatibility names:

```powershell
.\temp-cleanup.ps1 -RollbackFromManifest "C:\Users\labuser\Documents\Training\Day3\cleanup-work\manifests\manifest-20260805-051533.csv" -EnableRollback -DryRun
```

## Safety notes

- The script skips locked files and continues.
- Per-file errors are logged and do not stop the whole run.
- Cleanup is reversible only for files that were moved into the rollback store and still exist there.
- Review dry run output before doing a real cleanup on production endpoints.
- If you set `-OlderThanDays 0`, the script can target any file older than the current time, which is effectively most existing files in the target folders.
